# 運用プレイブック

## A. 新しい銘柄を追加する

1. ChatGPTへティッカーを入力
2. `full-refresh`で調査
3. `TICKER.report.json`を受け取る
4. JSON Validation
5. 非公開プレビュー
6. 情報量と表示を確認
7. draftのままPR
8. 人が承認後に公開

## B. 決算後に更新する

1. 現在の`TICKER.report.json`を添付
2. 最新決算・開示・株価を調査
3. `full-refresh`
4. 前revisionとの差分を確認
5. 計算を再実行
6. カタリスト・リスク・前提を更新
7. プレビュー比較

## C. 既存2ページ内のカタリスト要約だけ更新する

1. 現在の正本JSONを添付
2. `patch`を指定
3. ChatGPTはpatch JSONだけ出力
4. baseRevision一致を確認
5. patchを別ファイルへ適用
6. Validation
7. 変更項目だけ差分確認

## D. 専用カタリストレポートを追加・更新する

1. `TICKER.catalyst.json`を作成または更新
2. Catalyst Validation
3. `_report-preview/stocks/TICKER/catalysts.html`を生成
4. 日程、3結果、織り込み度、出典、情報量を確認
5. シナリオページとの整合を確認
6. draftの公開台帳エントリを作成
7. PRで人がページを確認
8. 人の確認者と確認日を台帳へ記録
9. 正本JSON、生成HTML、公開台帳を同じPRへ入れる
10. `published`へ変更した銘柄だけボタンを表示

専用ページがない銘柄は台帳へ登録しません。台帳の取得に失敗した場合も既存2ボタンだけを表示します。

## E. 誤りを訂正する

1. 誤った値と正しい一次情報を特定
2. 計算への影響を判定
3. 影響なし：`correction`
4. 影響あり：`full-refresh`
5. 更新履歴へ訂正理由を記録

## F. 株式分割・増資・M&A

1. `corporate-action`
2. 株数・現金・負債・転換条件を全面確認
3. Bear／Base／Bullを再計算
4. 分割前後の単位を明示
5. 旧レポートをそのまま使わない

## G. 株価だけ更新する

現在のサイトでは`prices.json`と`live-report-price.js`が担当します。

レポートJSONのシナリオ分析は変更しません。分析基準値とライブ株価を画面上で区別します。

## H. 古いレポートを順次移行する

1. 現行HTMLを基準値として保存
2. 当該銘柄の次回更新時にstructured JSONへ変換
3. 新旧プレビューを比較
4. 本文量・出典・セクションを検証
5. PASS後に当該銘柄だけ切替

62銘柄を一括変換しません。更新頻度の高い銘柄から順番に移行します。

## I. 定期点検

毎週：

- 決算通過銘柄
- 20%以上変動した銘柄
- カタリスト日程通過
- 株価取得エラー

毎月：

- 45日超の分析
- 出典リンク切れ
- schemaVersion
- 未移行銘柄

四半期：

- テンプレート変更
- 業種別必須項目
- Validationルール
- ロールバックテスト
